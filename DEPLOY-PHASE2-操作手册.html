Step A · Git 初始化 & 推 GitHub（7 步）

1
安装 Node.js LTS 并验证（已安装可跳过）
下载安装后新打开 PowerShell，复制运行： 
node -v       # 期望输出 v18.18+ / v20.x / v22.x
npm -v        # 期望输出 10+
不满足 → 回到上一段安装步骤。 Exit Code 必须 0。

项目根目录安装全局依赖（vercel + supabase CLI）

登录 vercel & supabase CLI
vercel login            # 会唤起浏览器授权；成功显示 "🎉  Congratulations! You are now logged in. "
supabase login          # 浏览器打开 https://supabase.com/dashboard/account/tokens/new?manual=true 创建 token，名字取 "local-cli"，粘贴回车
supabase link --project-ref 你的PROJECT_REF  # 粘贴 B 步骤拿到的 PROJECT_REF；输入 Database Password（创建 Supabase 项目时你设的）
# 成功 → Linked to project
4
生成 VAPID 公私钥（Web Push 必需）+ 记录 3 条值
cd "c:\Users\59643\Desktop\个人工作台"
npm install --no-audit --no-fund --loglevel=error        # 安装 @supabase/supabase-js + web-push 本地依赖（给步骤 5 gen-vapid 用）
node scripts\gen-vapid.mjs
✅ 控制台会输出： 
WEB_PUSH_SUBJECT            = mailto:your@email.example.com   （建议改成 mailto:你自己的邮箱）
WEB_PUSH_VAPID_PUBLIC_KEY   = xxx （长字符串）
WEB_PUSH_VAPID_PRIVATE_KEY  = yyy （长字符串）
重要：立即把这 3 条 + B 步骤的 4 条，先存在本地记事本 temp-env.txt，一会儿批量填入 Vercel Env。 ⚠️ 不要把 PRIVATE_KEY / SERVICE_ROLE_KEY 粘贴给任何人；.gitignore 已经忽略了 .vapid.json、secrets.json 等文件，不用担心泄露到 Git。
5
Supabase Migration 执行：清空 + 建表（Phase 2 要求"清空所有数据后部署"）
# 先执行 0000_reset_all.sql（清空云端旧数据；如果你的 Supabase 是全新空项目，这步可跳过）
supabase db reset        # ⚠️ 真的会清空云端所有业务表！执行前确认你就是要清空。
                         # 清空完成后自动跑 supabase/migrations/ 下的 0001_init_schema.up.sql
supabase db push         # 应用 0002_push_subscriptions.up.sql（Push 订阅表 + RLS）
supabase migration list  # ✅ 期望看到 0001_init_schema.up = Applied / 0002_push_subscriptions.up = Applied
坑：如果 db reset 报"数据库不可连接"→ 去 Supabase Dashboard → Database → Settings → Connection Pooling 把 IP 白名单加 0.0.0.0/0（临时允许所有；生产可收紧）。
6
初始化 git 仓库 → 首次 commit（避免出现"Everything up-to-date"推送空内容 — 参见 Experience 180240）
cd "c:\Users\59643\Desktop\个人工作台"
git init
git checkout -b main              # Vercel 默认监听 main；不要用 master（会推了不触发部署！）
git add -A
git status                        # 确认 ~20 个文件变绿；node_modules/.vercel/.env 等不应出现（已被 .gitignore 忽略）
git commit -m "chore: phase2 init — vercel static + supabase migrations + web push 4 templates"
git remote add origin 你的GIT_SSH_OR_HTTPS_URL   # A 步骤拿的 personal-workbench 远程仓库地址
# 先检查本地分支领先远端吗？领先才能推送内容！
git status
# 应该看到：On branch main / Your branch is based on 'origin/main', but the upstream is gone. — 说明首次推送，是对的
git push -u origin main
# ✅ 成功输出：Enumerating objects: ... done · Writing objects: 100% ... done
踩坑 Experience 180240：如果 git push 只输出 Everything up-to-date — 这表示远端没收到任何新提交！检查 ① 你是否漏了 git commit？② git branch 你在 main 还是 master？③ git remote -v 显示的 origin 对不对？解决后再 push。 踩坑 Experience 93071：push 报 Failed to connect to github.com port 443 after 21061 ms: Couldn't connect to server 是网络/代理受限：① 挂代理后设置 git config --global http.proxy http://127.0.0.1:你的代理端口；② 或改用 SSH Key（个人更稳）。
7
Vercel CLI 关联项目（不用浏览器 Import，命令行也 OK）+ 填 Env（8 条必填）

Step B · Vercel Deploy + 4 类系统推送触发验证（4 步）

8
第一次 git push 正式触发 Vercel 部署（或者命令行强制部署）
# 方式一（推荐）：直接推 main 分支 → Vercel 自动触发 Production Deploy
git commit --allow-empty -m "deploy: production deploy + env 已填"
git push
# 方式二（强制部署、跳过构建缓存）：
vercel --prod --yes --force
# 🔑 成功输出：🔗  Production: https://.vercel.app — 这就是你要的永久链接！✨
# 经验 585556：如果失败显示 ECONNRESET / 网络超时 → 加 --force 再试 2 次；还失败就改 GitHub 触发方式（方式一更稳）。
✅ 永久链接格式（不会变）：https://<项目名>.vercel.app。自定义域名要额外绑定。
9
打开 https://你的项目.vercel.app → 手机端 Chrome 或 iOS Safari（16.4+）→ 设置 → 开启系统级推送
  1. 首次打开：授权 HTTPS SW 注册正常 → 控制台 F12 应看到 [push] 未订阅推送 或 已订阅
  2. 进入「设置」 → 看到顶部 📱 系统级推送（手机锁屏可见）卡片 → 状态 pill = 🔔 未订阅推送 → 点【开启系统级推送】→ 弹窗「允许通知」→ 允许
  3. 接着会去后端拉 VAPID public key → /api/push/subscribe 返回 {ok:true} → 状态 pill 立即刷新为 ✅ 已开启推送
  4. 点【⚡ 发测试推送】→ 弹窗"已从后端发出推送" → 1~10 秒内手机锁屏或桌面通知栏出现"🌿 推送测试 · 手机锁屏可见"🌿 通知图标
❌ 失败排查：/api/push/subscribe 返回 501 MISSING_ENV → 回步骤 7，8 条 Env 有没有都填到 Production；返回 SUPABASE_WRITE_ERR → 回步骤 5 再做 supabase db push 再查 migrations；订阅弹窗返回"invalid curve point"→ 公私钥不匹配，重做步骤 4 生成 VAPID 并确保 public key（前端）和 private key（后端）是同一对。
10
Cron 系统推送触发验证（4 类模板）
不用真的等到 08:30；用手动 cURL 调 Vercel Functions 即可： 
# 10.1 晨间套餐（Cron：UTC 00:30 = 中国 08:30）
curl -X POST https://你的项目.vercel.app/api/push/morning
# → 返回 {"ok":true, cron:"morning", total, sent, gone410}

# 10.2 金币里程碑（10/20/50/100；先在 app 里让自己金币到 10 再调）
curl -X POST https://你的项目.vercel.app/api/push/coins-milestone

# 10.3 提醒到期（每 30 分钟扫描；先加一条今天的提醒再调）
curl -X POST https://你的项目.vercel.app/api/push/reminders

# 10.4 每周周报（Cron UTC 14:00 周日 = 中国 22:00 周日）
curl -X POST https://你的项目.vercel.app/api/push/week-report
4 条都返回 200 且 total>0 & sent>0 即通过 ✅；如果手机没收到？先检查设备系统通知开关（安卓 13+ 需要应用通知权限；iOS 横幅/锁屏显示模式要打开）。
11
数据 Supabase 迁移更新不影响用户数据：验证一次真实更新流程
  1. 在 Supabase Dashboard → Table Editor → profiles 里改 nickname="旭平"（任意值）。
  2. 在工作台创建 1 条新提醒（今日）+ 记一笔财富 → Supabase 对应表 records/wealth_tx 中立即出现 = 数据和代码分离 ✅
  3. 在本地改一行 CSS（比如财富抬头的颜色）→ git add . && git commit -m "chore: tune style" && git push → Vercel 自动部署 → 刷新链接看到新 UI 但数据不丢 = 代码更新不影响已有用户数据 ✅
  4. Phase 1 localStorage 的老用户：打开 app → 点「设置」→ 一键清空所有数据（wipeAllData）→ 重新登录，数据从 Supabase 拉回来正确 = Phase 1 → Phase 2 迁移平滑 ✅
